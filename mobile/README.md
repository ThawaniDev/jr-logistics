# JR Driver — Flutter app

Driver-facing Android/iOS app. Talks only to the Next.js API (`../web`) — no separate source of truth. UI state is **server-driven** (`actions` on each job), so the web portal and the app can never disagree about the next step.
Brand tokens (`lib/core/theme.dart`) match the web design tokens; strings come from the web dictionaries (`assets/i18n/*.json`, exported by `npm run i18n:export`), Arabic RTL / English / Urdu RTL.

**Features (Update L additions at the end):** username + password sign-in & registration (J1; a temporary password must be replaced at first sign-in; no one-time codes) · online/offline with explicit location consent · offers & open requests with terms · one-clear-next-step job screen (check-in, confirm loaded, report delivered with big stepper) · WhatsApp **hand-off** (prefilled localized message; we never send or read replies) · "can't reach recipient" exception · per-parcel **stops** worked one at a time (best route planned by the server with Google Routes — traffic-aware, or a clearly labelled estimate —, shown as a route summary with distance / driving time / warnings, a per-stop driving leg and location badges; the driver reviews and approves it, can **re-optimise** it from where they are (before and after approving) and open the next stops in **Google Maps**; call / WhatsApp / navigate per stop; delivery code or receipt photo; unreachable wait timer; failure reasons) · in-app chat · earnings, withdrawals · documents (camera/gallery) · notifications.

```bash
flutter pub get
flutter run --dart-define=API_BASE_URL=http://localhost:3000       # Android emulator default: http://10.0.2.2:3000
flutter analyze && flutter test                                    # unit + widget tests (network, double-submit, sign-in states, receipt upload, error mapping, RTL / text scale)
./tool/live_test.sh                                                # spins up the real server + test DB, runs the live API tests (incl. the best-route one)
./tool/live_test.sh --e2e                                          # + full journey on the iOS simulator (DEVICE="iPhone 17 Pro")
```
Release builds require HTTPS (cleartext is only allowed in the Android debug manifest). Store listing, signing, push notifications and a true offline queue are not part of this version (poor-network behaviour: retries on reads, stale-data strips, no-double-submit and outcome verification on writes) (see `../memory/DECISIONS.md` #15).

## Field operations: route map, cash, offer alerts, support (decisions E6, E11, E12, E15, E17, E18)

- **Route map** (`/job/:id/map`, `RouteMapButton(offerId)` for the job screen): `flutter_map` with OpenStreetMap tiles — no Maps SDK key. The coloured legs come from `GET /driver/jobs/:id/route-geometry` (Google encoded polylines, precision 5, decoded in `lib/data/models_extra.dart`; a leg without a polyline is a **dashed straight line**, and if the geometry cannot be loaded at all the map still draws dashed lines between the stops). Markers are lettered A–Z (then numbered) in route order; stops with no map position are listed, not drawn. Tapping a marker or a row opens a popup with the stop's details and only the actions the server allows (`work_stops`, current stop, `route.canReorder`), executed by the shared `StopActions`.
  Tiles: `--dart-define=MAP_TILE_URL=https://…/{z}/{x}/{y}.png` (default `https://tile.openstreetmap.org/{z}/{x}/{y}.png`). **Owner item:** OpenStreetMap's public tile servers are for light use (OSM Tile Usage Policy); before a real launch point `MAP_TILE_URL` at a commercial or self-hosted tile service. The user agent is `com.jrlogistics.jrDriver` and the attribution "© OpenStreetMap contributors" is always shown.
- **Cash with me** (`/cash`, card on the home screen): `GET /driver/cash` — collected / handed over / with me, per order, recent hand-overs. COD cash is the warehouse's money and never touches the wallet; the warehouse records each hand-over.
- **One active job** (E11): `GET /driver/offers` / `/driver/opportunities` answer `{items, hidden, activeJob}`; while `hidden` the Offers screen explains "finish your current job" and links to that job; the home screen shows an "Active job" shortcut from `overview.activeJob`.
- **New-offer alerts** (E12): while the app process is alive it polls `GET /notifications?unreadOnly=1` (about every 20 s in the foreground, every 60 s while backgrounded but still running, immediately on resume) and raises a **local** notification (Android channel `offers`, high importance, sound + vibration; iOS alert + sound), a haptic, an in-app banner and a dot on the Offers tab for every unseen `offer_new` (deduplicated by notification id, remembered across restarts; offers older than 6 h are not announced). Tapping the notification opens the Offers tab. Permission is asked politely from a card on the home screen (Android 13+/iOS), never at launch. Code: `lib/services_notify.dart` (poller, notifier), `lib/features/home/notify_host.dart`.
  **What this is not:** true background push. A phone that is locked for an hour or an app the OS has killed receives nothing until the driver opens the app. That needs **FCM (Android) and APNs (iOS) credentials plus a server-side sender — an owner item**; the poller then becomes a fallback.
- **Support tickets** (`/support`, `/support/new`, `/support/:id`; "Support" row in Profile): list with status badges, urgent flag and a dot on tickets with news; new ticket (category from `GET /catalog` → `ticketCategories.driver`, optional related job, up to 3 photos via `POST /uploads/ticket`); thread with role badges, photo thumbnails fetched with the auth header, reply with photos, resolve, and **Reopen** within 14 days of resolving.
- **Wallet** (E18): earnings arrive automatically when a job ends; the "pending" figure now means **on hold** (an open complaint holds the payment). Withdrawals keep their manual approval.

Tests for all of this: `test/unit/mobile_b_*.dart`, `test/widget/mobile_b_*.dart` (fakes in `test/helpers_extra.dart`; the route-map, cash, offers, notifications, support and wallet screens, plus a 320 dp × 1.4x text sweep in en/ar/ur). The single live case (`cash with me + support tickets …`) is at the end of `test/integration/live_api_test.dart`.


## Platform notes (audit K / A6)

- **Location is foreground-only.** The app reports the driver's position (every 90 s) and measures the arrival distance only while it is open; a phone that is locked or showing Google Maps sends nothing. Background location needs `UIBackgroundModes: location`, `ACCESS_BACKGROUND_LOCATION` + a foreground service and store review — an **owner decision** (memory/audit/mobile.md D1).
- **Signing out takes the driver offline** (`PUT /driver/availability {available:false}` + `DELETE /driver/location`, best effort, then `/auth/logout`). A session the server already ended (401) cannot do that; ops can still set the driver offline.
- **Long lists are paged by the server** (finished jobs 100, wallet entries 50, notifications 30): each list ends with "Load more" while the server holds more.
- **Native launch screens follow the system appearance** (iOS `LaunchBackground` colour asset with a dark variant used by `LaunchScreen.storyboard`; Android `values/colors.xml` + `values-night/colors.xml`, plus the Android 12 splash in `values-v31` / `values-night-v31`). Colours = the app's `bg` in light and dark. When the in-app theme is forced against the system setting the first frame can differ briefly.
- **Install marker.** `install_marker` in shared_preferences is written on the first launch; when it is missing (fresh install) a session token left in the iOS keychain by an earlier install is dropped. Upgrading from a build that did not have the marker signs the driver in again once.
- A release build must be given `--dart-define=API_BASE_URL=https://…`; without it the app shows a configuration error instead of silently talking to localhost.


## Update L: updates, legal, privacy, cash limits, SMS off, crash reports, store hygiene

Strings: the texts come from the web dictionaries — the app's own are `lm.*` (`web/src/i18n/fragments/rd-l-mobile.ts`); it reuses `cr.*` (cash), `pv.*` (privacy), `lg.*` (legal), `gp.invite_blocked_*`, `co.help_*` and `err.*`. After editing run `cd web && npm run i18n:export` once.

- **Version headers and forced update.** Every request carries `X-Client: mobile`, `X-App-Version: <version>+<build>` (read from the installed bundle with `package_info_plus`, so `--build-name` / `--build-number` are honoured; `AppConfig.version` / `build` are the fallback and a test keeps them equal to `pubspec.yaml`) and `X-App-Platform: ios|android`. The server answers `426 UPGRADE_REQUIRED` `{minVersion, currentVersion, platform, storeUrl}` (not for `GET /catalog` and `GET /health`) to a build below the minimum set in Settings › General › Mobile app. The whole app is then replaced by a full-screen, non-dismissable update page (`lib/features/update`) whose button opens `storeUrl`; on a cold start the same page appears when the catalog's `policy.app.minVersion[platform]` is above the installed version (the catalog is exempt, so an outdated app can read it). "I have updated" re-reads the catalog. **Owner items:** fill in the store links (iOS App Store URL, Google Play URL) and the minimum versions in the web settings; without a link the page tells the driver to open the store by hand. When you bump the version, change `pubspec.yaml` and `AppConfig` together.
- **Minimum OS: iOS 15, Android 8 (`minSdk = 26`).** Set in `ios/Runner.xcodeproj`, `ios/Podfile`, `ios/Flutter/AppFrameworkInfo.plist` and `android/app/build.gradle.kts`.
- **Terms and privacy.** Profile › *Terms and conditions* / *Privacy policy* open readers (`/legal/driver`, `/legal/privacy`: `GET /legal/:kind?lang=`, a small safe markdown renderer, no HTML, no WebView). The registration screen shows both texts before the single acceptance box. When `GET /auth/me` → `legal.pending` is not empty (a new version asked for re-acceptance) the router keeps the driver on `/legal-accept` (reader + accept → `POST /legal/accept`; a `409` reloads the list); `/auth/me` is read at start, after sign-in and when the app comes back to the front.
- **Privacy & data.** Profile › *Privacy & data*: *download my data* (`GET /privacy/export`, a JSON attachment → the platform share sheet through `share_plus`), *delete my account* (`GET /privacy/status` lists what blocks it, `POST /privacy/delete-request`, withdraw with `/cancel`). The team approves each request; once it is approved the next call answers `401` and the app returns to the sign-in. Apple requires this in-app route. Code: `lib/data/privacy_repo.dart` (the only place that knows the URLs), `lib/features/privacy`.
- **Cash limits.** `overview.cash` (`state`, `blocksOffers`, `lienCents`, …) drives a banner on Today and Cash with what to do (hand the cash to the warehouse), a "paused" state on Offers when the server answers `{items: [], cashBlocked: true, cash}`, a dialog for `403 CASH_LIMIT` on accept / apply, `409 CASH_OUTSTANDING` on withdrawals (the wallet shows the part that cannot be withdrawn and limits the amount), and the age of each order's cash (`ageDays`).
- **SMS off.** A stop with `needsOtp: false` shows no code box and no resend button; `otpOffReason: sms_off` says why in plain words; `POST …/resend-code` → `{sent: false, smsOff: true}` is handled.
- **Invitations.** `GET /driver/invites` → `walletBlock`: while the wallet holds money (or a withdrawal waits) the invitation is shown with its explanation and Accept is off; a `409 WALLET_NOT_EMPTY` is explained too.
- **Notifications.** The new types (`cash_*`, `document_expiring`, `balance_moved_to_office`, `stop_marked_*`, `parcels_added`, `recipient_corrected`, `offer_rescheduled`, `broadcast`, `privacy_request_*`) have text, icon and a target; a broadcast's `link` (a web path) is mapped to the matching app page.
- **Support contact.** `GET /catalog` → `company` (Settings › Company on the web): a *Contact support* card with call / WhatsApp / e-mail on the sign-in screen and in Profile; hidden while no channel is filled in.
- **Crash reports (self-hosted).** `lib/core/crash_reporter.dart`: `FlutterError.onError`, `PlatformDispatcher.onError` and `runZonedGuarded` keep the app alive and send a scrubbed report (message with tokens / e-mails / phone numbers / query strings removed, stack ≤ 4 KB, screen name without ids, app version, platform, OS version, time — never a token, a name, a phone number or a request body) to `POST /api/v1/app/errors`, without the session token. At most 5 per run, identical ones once, "no signal" errors never, failures are dropped (no retry). No third-party vendor is installed — the owner has not chosen one; to add Sentry / Crashlytics later, replace `httpReportSender` (or add a second sender) in `main.dart`.
- **Store hygiene.** `ITSAppUsesNonExemptEncryption = false`; `ios/Runner/PrivacyInfo.xcprivacy` (no tracking, UserDefaults `CA92.1`, the collected data types — review them with the owner against the App Store Connect privacy questionnaire; the plugins ship their own manifests); `InfoPlist.strings` for English, Arabic and Urdu (`ios/Runner/<lang>.lproj`, listed in `CFBundleLocalizations`) so the permission dialogs speak the driver's language; Android: camera `required="false"`, `allowBackup="false"` plus `dataExtractionRules` / `fullBackupContent` that exclude everything. Background location stays **off** (owner decision D1; `test/unit/lm_platform_test.dart` pins it).

**Owner items (not done here):** the release **signing** (Android keystore + `signingConfig`, iOS team / provisioning profile), the final **`applicationId`** / bundle id (now `com.jrlogistics.jr_driver` on Android and `com.jrlogistics.jrDriver` on iOS — they differ; pick one reverse-DNS name for both before the first store upload, it cannot be changed afterwards), store listings and screenshots, the store links and minimum versions in the web settings, the support channels in Settings › Company, and the App Store Connect privacy questionnaire / Google Play Data safety form (use the data types of `PrivacyInfo.xcprivacy`).

Tests for all of this: `test/unit/lm_*.dart` (version / 426 / headers, crash reporter, markdown + legal state + router rules, models + texts + notification types, platform files) and `test/widget/lm_*.dart` (update page, legal readers and gate, privacy, cash, SMS off, invitations, support contact, notifications, 320 dp × 1.4x sweeps in en / ar / ur).

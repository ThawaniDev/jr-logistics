# Platform data, reports and detail views (decisions G1–G12)

Owner request (2026-11-19): (1) as superadmin I can't find *add company / office / driver / user*; (2) reports must be far more advanced and reliable with many filters, a **main sidebar group**, and the platform must **collect much more data** for advanced reports; (3) every detail page (support ticket, order, driver, company, office …) must show far more data and logs, not just a little; "make it a big, powerful platform with a lot of analysis, not a small platform with poor data".

## Decisions
| # | Decision |
|---|---|
| G1 | **Staff can create accounts.** Admin/staff with `accounts.create` add companies, offices, drivers and users (staff already exist) from the list pages (`/admin/companies/new`, `/admin/offices/new`, `/admin/drivers/new`, `/admin/users/new` = chooser). The account is created like a self-registration (same validation, wallet, profile) but `users.source='admin'`, `users.created_by=<staff>`; the person signs in with the phone through the normal OTP flow. Staff can also edit an account's profile. Everything is audited (`account.create` / `account.update`). |
| G2 | **Reports is a main sidebar group**: Overview · Operations · Deliveries · Revenue & finance · Companies · Drivers · Courier offices · Cash on delivery · Support & quality · Geography · Growth & onboarding · Data explorer (+ Ratings). One page per report (F1). Companies and offices get their own *Reports* group (own data only). |
| G3 | **One filter model everywhere** (`server/analytics/filters.ts`): period (`from`/`to` Riyadh calendar days or a preset), `bucket` (auto/hour/day/week/month), `compare` (none / previous period / same period last year), and multi-value `city`, `service`, `vehicle`, `company`, `office`, `driver`, `status`, `channel`. URL-synced; every report page, KPI, chart, table and CSV export uses the same filters. |
| G4 | **Report anatomy**: KPI row with delta vs the comparison period → trend chart(s) → breakdowns (by city/service/vehicle/company/…) → distributions (histogram/percentiles p50/p90) → rankings (top-N + bottom-N) → drill-down table (paged, sortable, CSV). Every number has a definition tooltip. Charts use recharts + tokens (colour-blind-safe palette), RTL-safe, with a data-table alternative. |
| G5 | **Collect more data** (migration 0012): login events + last-seen, location history, driver availability log, per-parcel event log, outbound message log, request milestone timestamps, ticket/complaint first-response times, hourly/daily platform snapshots (supply, demand, wallet liability, escrow, cash with drivers …), internal staff notes on any entity. See `memory/DATA_CAPTURE.md` (written by the data workstream). |
| G6 | **Activity log is a shared service**: `entityActivity()` merges every source about one entity (audit log, job events, parcel events, notifications, chat, ledger, replies, notes, logins, messages …) into one permission-aware, filterable, paged feed; UI `<ActivityLog entity id/>` + `<NotesPanel/>`. Every detail page embeds it. |
| G7 | **Detail pages minimum**: header with state + key facts → KPI/performance strip (entity analytics) → related items (orders, parcels, tickets, complaints, money) with links → full timeline/activity log → internal notes → raw data panel (ids, timestamps, JSON for support). |
| G8 | **No guessing numbers**: every KPI has one definition in code (`server/analytics/definitions.ts`) shown in the UI; percentages say their denominator; empty periods show "no data", never 0%. |
| G9 | **Demo history**: `npm run db:seed:history` generates months of realistic activity for the demo accounts so dashboards can be judged (opt-in, dev/demo only, refuses to run in production, marks rows). |
| G10 | **Permissions**: `reports.view` for all analytics (finance reports additionally `finance.view`), `reports.export` for CSV/explorer, `audit.view` for raw audit entries inside activity logs, `drivers.sensitive` for personal data; the activity feed drops sources the viewer may not see and says so. |
| G11 | **Performance & reliability**: reports run bounded SQL aggregates (no row loops), time-boxed (statement timeout), cached for 30 s per filter set, and never load more than a page of detail rows. Indices are added by migration when a report needs them. |
| G12 | **Portals get their own reports**: companies (deliveries, spending, COD) and offices (drivers, earnings) see analytics scoped to their own data, same components. |

## Ownership (parallel workstreams)
Phase 1 (foundations): **reports framework + Overview** (`server/analytics/**`, `components/reports/**`, `rpf.`), **data capture + activity log** (`db/schema.ts`, migration 0012, capture wiring, `server/activity.ts`, `dtk.`), **account creation** (`acr.`).
Phase 2 (on top of the foundations): report packs (`rpo.`, `rpd.`, `rpp.`, `rpq.`), detail views (`dv1.` orders+parcels, `dv2.` drivers+offices, `dv3.` companies+users+tickets+complaints), demo history seed.
Shared and owned by the lead: `components/ui/*`, `components/layout/*`, `i18n/fragments/index.ts` + `redesign-core.ts`, `server/api/routes/index.ts`, `memory/*.md` indexes.

## As built (2026-11-19)
- **Account creation (G1/G1a):** `POST /admin/accounts`, `PATCH /admin/accounts/:id`, `GET /admin/accounts/check|office-options|:id` (`server/account-admin.ts`, `account-admin-rules.ts`); pages `/admin/{companies,offices,drivers}/new` + `/…/[id]/edit`, `/admin/users/new` (chooser); permissions `accounts.create` / `accounts.edit` (operations + hr_verification presets); company VAT number (`business_profiles.tax_number`).
- **Data capture (G5):** migration 0012 (+0013 tax number, 0014/0017 indexes). Tables and capture points in `memory/DATA_CAPTURE.md`.
- **Activity log (G6):** `GET /admin/activity/:entity/:id`, notes `GET|POST /admin/notes/:entity/:id`, `<ActivityLog>` / `<NotesPanel>` / `<RawDataPanel>` embedded in every detail view.
- **Detail views (G7):** order `/admin/requests/:id/(drivers|parcels|money|communication|activity)`, parcel `/admin/parcels/:id` (+ search `/admin/parcels`), driver and office (12 / 10 sections), company (12 sections), user `/admin/users/:id`, ticket `/admin/cases/:id` and complaint `/admin/complaints/:id` with SLA clocks, requester/related-entity cards, notes and activity.
- **Reports (G2–G4, G8, G11, G12):** see `ANALYTICS.md` §12. 11 admin report pages + Data explorer + 6 portal report pages.
- **Demo history (G9):** `npm run db:seed:history -- --yes` (see `DEMO_HISTORY.md`; refs `JRH-/TKH-/CPH-…`, users `source='seed'`); dev DB currently holds 180 days (≈3.2k requests, 21k parcels, 111 users).

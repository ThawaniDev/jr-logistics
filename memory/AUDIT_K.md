# Audit K + light mode (2026-11-21)

Owner request: *"Make general auditing and find gaps and issues, technical and logical issues, and make the platform and the mobile app support light mode also."* Standing rules: take recommended defaults and move on (no check-ins), test everything end to end, report honestly what is verified, keep the UI consistent, no commits.

Platform context: `web/` (Next.js 16 + Postgres/Drizzle, UI + `/api/v1` in one app), `mobile/` (Flutter driver app). Read first: `web/AGENTS.md` (Next 16 differs from your training data), `memory/DECISIONS.md` (why things are the way they are — A…J series; do not "fix" a decision, flag it), `memory/ANALYTICS.md`, `memory/UI_REDESIGN.md`, `memory/PLATFORM_UPDATE_J.md` (the latest changes: username login, routing/B2B settings, office-driver wallet, roles, finance drivers, readable CSV), `memory/TRACEABILITY.md`, `memory/PRD.md` / `SRS.md` when your area needs them.

## Two kinds of workers

* **Auditors** (areas A1–A8 below) audit **their own area first, then fix what they confirm** — in the same pass — with tests. Method: read the code paths for real, then *prove* each finding (a failing test, a reproduction with curl/psql/script against the dev server or test DB, or a precise code argument for races/invariants). **Do not report guesses**: every finding states confidence (confirmed / probable) and how it was verified. Prefer finding few real problems over many speculative ones. Look for **technical** issues (bugs, security holes, races, missing validation, N+1 / slow queries, timezone/rounding errors, resource leaks, broken error handling, dead code, flaky tests) and **logical** issues (state machines that allow impossible transitions, money that does not add up, permissions that do not match the UI, features that contradict a decision, edge cases: empty/zero/huge/unicode/RTL/timezones/DST-free Riyadh vs UTC at 21:00–24:00 UTC, concurrency, retries/idempotency, partial failure) and **gaps** (things the PRD/decisions promise that are missing, half-built flows, dead ends in the UI, missing empty/error states, missing audit trail, missing indexes).
* **Light-mode workers** (L1 web, L2 mobile): see below.

## Severity and what to fix
critical (data loss, money wrong, auth bypass, PII leak, crash of a core flow) and high (wrong behaviour in a core flow, exploitable weakness, serious perf) → **fix now**, with a regression test. medium → fix when local and safe (same area, no product decision). low → fix only if trivial; otherwise list. Anything that needs a **product decision** → list under "Needs owner decision" with a recommended default and implement the default only if it is reversible and cheap. Never rewrite a whole module to fix a medium; never change a documented decision (DECISIONS.md) silently — flag it.

## Deliverable of every auditor
`memory/audit/<area>.md` (create the folder): a short summary, then a findings table `# | severity | confidence | where (file:line) | issue and impact | how verified | status (fixed + test / open / needs decision)`, then "Needs owner decision", then "Checked and fine" (a bullet list of what you looked at that is OK — so nobody repeats it). Keep your final reply to the lead **short** (counts by severity, the 5 most important findings, tests run, anything the lead must do).

## Light mode (L1 web, L2 mobile) — design decisions
Modes: **system (default), light, dark**; user choice persisted per device. Dark stays exactly as it is today. Light palette (WCAG AA): the semantic tokens keep their names; light values proposed — bg `#f6f8fb`, bg2 `#edf1f7`, card `#ffffff`, text `#0f172a`, muted `#526179`, line `#d5dde9`, accent `#047857` (text/links/buttons; `accent-ink` `#ffffff`), cyan `#0e7490`, gold `#b45309`, danger `#dc2626` — adjust if a contrast test says so (text pairs ≥ 4.5:1, UI boundaries ≥ 3:1; add a unit test that computes them for **both** themes). Status/tint usages (`bg-accent/10`, `text-danger`…) must stay readable in both. Charts, maps, modals/backdrops, shadows, skeletons, selection, scrollbars, the select arrow, logo, landing page hero, print styles and exports/PDF sheets (invoice print sheet must stay black-on-white in both themes) are part of the job.
* **L1 web** (owner of `globals.css`, theme provider/toggle, `app/layout.tsx`, `components/reports/chartTheme.ts` and every file that has hard-coded colors): tokens + `data-theme` on `<html>` set before first paint (cookie `jr_theme` read on the server + a tiny inline script for `system`; no flash, no hydration warning), `color-scheme`, a **Theme menu** (System / Light / Dark with icons) in the app shell top bar, the public pages header, and the profile pages; persistence in `localStorage` + cookie; i18n keys (`rd-k-l1.ts`), tests: unit (contrast of token pairs in both themes, theme resolver) and e2e `e2e/theme.spec.ts` (toggle persists across reload and navigation, `system` follows `prefers-color-scheme` (Playwright `colorScheme`), no hydration errors, key pages render in light without horizontal overflow). Then **visual QA**: screenshot every sidebar page of every role (admin, staff, business, driver, office) + login/register/landing/track in light (1360 and 390 px, English and Arabic) with a script like `web/e2e/crawl`-style or ad-hoc Playwright against the dev server, LOOK at them, fix everything that is unreadable/unbalanced (white text on white, dark chips on light, invisible borders, charts with dark-only palettes, maps). Report what you checked.
* **L2 mobile** (owner of `mobile/lib/core/theme.dart` and the **mechanical migration of every `JR.*` colour use**): `JR` colours become getters over the active palette (`JR.bg`, `JR.card`… keep their names so call sites stay readable); remove the 300+ `const` contexts that break (loop: `flutter analyze`, remove the offending `const`, repeat — script it); `buildTheme(Brightness)` for light and dark; `ThemeMode` provider (system/light/dark) persisted in shared_preferences, a Theme row in Profile (bottom sheet with 3 options, i18n keys in `web/src/i18n/fragments/rd-k-l2.ts`), the root re-keys the navigator on a theme change so every widget re-reads the palette without losing the router location; replace hard-coded `Colors.white/black`/`Color(0x…)`; status bar / system UI overlay style per brightness; map tiles, signature pad (dark ink on white paper in both), QR/scan overlays, shadows, shimmer/skeletons, badges/chips tinted with `withValues(alpha:)` must stay readable; native launch screen stays dark (note it). Tests: palette contrast unit test for both themes, the existing overflow sweeps run in **both** modes, golden-less widget tests for the toggle and persistence. `flutter analyze` clean, `flutter test` green. Screenshots: render key screens offscreen/on the simulator in light and dark and LOOK at them (login, today, jobs, shipment list/card, wallet, profile, deliver sheet).

# A5 — Web UI, accessibility and i18n (audit K, 2026-11-21)

Status: **phase 1 (read-only audit) and phase 2 (fixes + light/dark re-crawl) finished** — see "Phase 2 — what was fixed and re-verified" below.

## Summary

* Method: an automated browser crawl (`web/e2e/crawl.spec.ts`, helpers `crawl-lib.ts`, `crawl-dom.ts`, `crawl-routes.ts`, `crawl-report.ts`, config `web/playwright.crawl.config.ts`) against the **dev server :3000 / dev DB** (read-only, navigation only), plus static scans (TypeScript AST scripts) over `src/`.
* Crawl size: **1,657 page loads, 37 runs, 291 distinct (account × route pattern)**. Accounts: `admin`, staff `demo.support`, staff `demo.finance1`, `demo.business`, `demo.driver`, `demo.driver5` (office-linked), `demo.office`, plus signed-out pages. Every sidebar route of each account plus every detail route reachable by links (breadth-first over `<a href>`, up to 2 instances per route pattern; route coverage is compared with the `page.tsx` files). Matrix: English + Arabic × 1360 px desktop + 390 px phone (touch emulation) for everybody; Urdu × desktop for admin/support/business/driver/office as a spot check. Old URLs (`/admin/cod`, `/admin/pricing`, `/admin/finance?tab=`, `/admin/verification?tab=`) were followed too. Unreached routes: only `/admin/integrations/orders/:id` and `/business/integrations/orders/:id` (no partner orders exist in the dev DB).
* Per page the crawl asserts: console errors/warnings, `pageerror`, hydration warnings, failed or 4xx/5xx same-origin requests, Next dev overlay, sideways overflow (and the guilty element), `<h1>` count, `<main>` count, raw i18n keys, `undefined`/`NaN`/`[object Object]`/`Invalid Date`, unreplaced `{placeholders}`, Eastern-Arabic digits, `<html lang/dir>`, buttons/links without accessible name, inputs without label, images without alt, duplicate ids, positive tabindex, heading order, touch targets < 24 px (phone only), skeletons still on screen, English sentences in an RTL locale, "1 xs" plurals. A separate test probes the restricted staff roles on admin URLs they do not have in the sidebar, and a third one drives the dialogs (focus in, Tab, Esc, focus back).
* Static: en/ar/ur parity and placeholders, every `t("literal")` key exists, error codes, enum coverage, hard-coded English in JSX/attributes/toasts, physical `left/right` classes, double-submit guards, `run()` calls without a refresh, clickable rows, `<Modal>` usage.
* **Result of phase 1: 0 critical, 1 high (a regression from L1's in-flight theme menu), 7 medium, 12 low** (statuses after phase 2 are in the table). No 5xx, no failed request and no page error on any of the 1,657 loads; no raw keys (except permission codes shown on purpose), no `undefined`/`NaN`, no Eastern digits, no wrong `lang`/`dir`, no unnamed control, no unlabeled input. The area is in good shape; the real problems are layout (phone width), the permission-denied experience, tab titles, and a few shared-component details.
* Caveat for the lead: the dev server is also being edited by L1 while this ran (theme menu appeared in the top bar mid-run). Findings that depend on L1's work are marked **(L1)**; the phase-2 crawl in light and dark re-checks them. Two events were seen once and could **not** be reproduced (see "Not confirmed").

## Needs owner decision (recommended defaults)
1. **Permission-denied UX (W-3).** Recommended: a calm "no access" page (with `<h1>`) from a Shell-level guard + a 403 variant of `ErrorState`, and **keep** showing links (hiding every link by permission is a large change across hundreds of cross-links). Alternative: permission-aware links through one `<AppLink perm>` wrapper — more work, better polish.
2. **Plurals (W-9).** Recommended: add optional `key_one` variants, English only for the ~20 most visible keys; Arabic/Urdu wording stays number-neutral. Full ICU plurals (Arabic has 6 forms) is not worth it now.
3. **Top bar on phones (W-1).** Recommended: below 430 px the theme menu lives in the drawer + public header collapses to icon-only language/theme buttons; the wallet chip shows the number only. (L1 and A5 touch the same lines — one of us only.)
4. **Scenario bank (W-16)** stays Arabic-only (internal tool).

## Checked and fine
* **i18n parity:** ar/en/ur have the same 10,413 keys, no empty value, placeholders identical in all three (script + existing `tests/unit/i18n.test.ts`); 24 (ar) / 31 (ur) values equal the English one — all brand/technical terms (Logestechs, IBAN, `{n} ms` …). All 45 `ErrorCode`s have `err.*` keys in the three languages. 18 duplicate keys across fragments (same sentences, later wins) — harmless.
* Every literal `t("…")` key used in `src` exists; dynamic namespaces (`status.*`, `event.*`, `dtk.p_*`, ledger kinds…) cover the values in the dev DB (checked every enum-like column against the dictionaries; the only misses are not rendered through those namespaces).
* **Hard-coded English in components:** none in JSX text, `placeholder/title/aria-label/alt/label`, toasts (AST scan of 400+ files); only `JR Logistics`, technical samples (`05XXXXXXXX`, curl snippet) and the Arabic-only scenario page.
* **Formatting:** one place (`lib/format.ts`): Latin digits (`nu-latn`) in ar/ur, Riyadh time zone, SAR; no Eastern-Arabic digits on any of 1,657 loads; no `toLocaleString()` with the browser zone.
* **RTL:** `left/right/ml/mr/pl/pr/text-left/text-right/float` classes appear only in the scenario page; directional icons (`ChevronRight`, `ArrowLeft`, `LogOut`, …) all carry `rtl:rotate-180`/`-scale-x-100`; `<html lang/dir>` correct for en/ar/ur everywhere.
* **Accessibility:** zero buttons/links/inputs without an accessible name or label on all pages; images have `alt`; `Field` wires `label/for/aria-describedby/aria-invalid`; `Table` scroll regions focusable; `Segmented`/`Tabs` keyboard behaviour; skip link + `#main`; icon-only controls have `aria-label`; clickable table rows always contain a real link or button.
* **Dialogs** (`<dialog>` modal): focus moves in, Esc closes, focus returns to the opener, background is inert (Tab only cycles through the dialog and the browser chrome), dialog has an accessible name — checked for the top-up form and the ⌘K switcher in en and ar.
* **Double submit:** every mutation goes through `useAction.run` (ignores a second call with the same key), a local lock (`login`) or a disabled/loading button; AST scan found 11 async functions calling `post/patch/del` without the usual guard words and all 11 are guarded (login lock, `.run` wrappers, upload helpers). `0` `run()` call sites with a mutation and no refresh.
* **Routes:** no 404s from links (only the intentional `/no-such-page`), old URLs redirect (`/admin/cod`, `/admin/pricing`, `/admin/finance?tab=`, `/admin/verification?tab=`), `/scenarios` is guarded by `settings.view|edit` on the server.
* **Stability:** 0 × 5xx, 0 failed requests, 0 page errors, 0 `undefined/NaN/[object Object]`, no raw keys except the permission codes in `/admin/roles` and the user page (shown on purpose, monospace, next to the label).
* **Speed (dev server):** median 1.5–2 s per admin page, p95 7.4 s, max 16 s (first compile + the heavy report pages `/admin/reports/drivers|offices` and `…/:id/reports`: API 2–4 s). Skeleton still on screen after 9 s on those pages was a false alarm (a `<details>` that is closed holds a skeleton) — the crawl now ignores closed disclosures.

**Found and fixed during phase 2 — W-21 (high, caused by my own title fix, caught by the crawl):** the first version of `useDocumentTitle` re-asserted the title with a `MutationObserver`; `driver-alerts.tsx` has an observer of its own that puts "(n) " in front of the title, so the two rewrote each other without end and **every driver page froze** ("Page crashed" in 8 of 8 driver crawl runs). ## How to run the crawl
```
cd web
CRAWL=1 npx playwright test -c playwright.crawl.config.ts                      # everything (~15 min, 4 workers)
CRAWL=1 CRAWL_ONLY=admin,business CRAWL_LOCALES=en CRAWL_VIEWPORTS=desktop npx playwright test -c playwright.crawl.config.ts
CRAWL=1 CRAWL_ONLY=dialogs npx playwright test -c playwright.crawl.config.ts    # focus handling of dialogs
npx tsx e2e/crawl-report.ts default [--cat=overflow] [--run=admin-ar] [--unvisited]  # summary
```
Targets the running dev server (`CRAWL_BASE` to change); signs in through the API with the demo accounts (admin password from `.env.local`); results in `web/.crawl/<theme>/*.json` (git-ignored; **not** under `test-results/`: any other Playwright run in `web/` empties that folder — it deleted my first two result sets). `CRAWL_THEME=light|dark` sets the `jr_theme` cookie; `CRAWL_STRICT=1` fails on high findings. The spec skips itself without `CRAWL=1`, so the normal `npx playwright test` (test DB, port 3101) does not run it.

# A8 — Product gaps vs requirements (audit K, 2026-11-21)

Read-only gap analysis of `web/` + `mobile/` against `PRD.md`, `SRS.md`, `TRACEABILITY.md`, `DECISIONS.md` (A…J series), `FLOWS_*`, `PLATFORM_FULL_SPEC_AND_FLOWS_EN.md`, `PLATFORM_UPDATE_J.md`.
Value H/M/L = business impact if left; Effort S (< 1 day) / M (1–4 days) / L (> 4 days). "Recommended default" is what to build if the owner does not answer.

**Totals:** 16 build-next, 12 later, 16 decide-with-owner, 1 tiny fix applied (and tested). Plus 9 requirement contradictions/misses, 12 interplay problems of the latest changes, 5 cross-area findings.

## How this was done (and the limits)
* Read all the requirement documents above, then walked the product as **8 personas** on the dev server (`:3000`): `admin`, `demo.ops`, `demo.finance1`, `demo.hr`, `demo.support`, `demo.business`, `demo.driver`, `demo.office` — Playwright visited every sidebar page (about 150 page loads, Arabic UI, 1360 px, screenshots kept in the scratchpad), recording failed `/api/v1` calls and console errors. Result: **no 4xx/5xx on any sidebar page for any persona**, no empty/broken page. Two console errors seen (see Cross-area).
* Built an inventory of all **344 API routes** (`method/path/auth/perm`) and matched each with a UI or Flutter call by string match, then manually resolved the ~77 non-matches (most are dynamic template paths, public/partner/cron endpoints by design).
* Probed the dev DB (`psql`) and the API with curl for the money/permission interplays quoted below (every number is from the dev DB at the time of the audit).
* **Not exercised:** the Flutter app itself (code + `driver_api.dart` read only, the lead runs the simulator), the `account_manager` and `reports` staff presets (no demo account; analysed from the permission catalogue only), deep clicks through every modal.

## 6. Journeys per role — what was walked, dead ends found

* **Business** — register → documents → verification → wallet → new request → publish → track → cash → invoices → API/webhook → integrations. Dead ends: funding in production (B1); published order cannot be edited or rescheduled (B14); recipient typo after hand-over (O8); no webhook replay (B12); no team/branches (L1); no invoice with seller identity/ZATCA (B3/O3); cannot cancel after the driver arrived except through an urgent-help ticket (by decision #8/B3, no fee).
* **Driver (direct)** — register → documents → verification → availability → offers/opportunities → job → loading scan → stops → cash → wallet → withdrawal. Dead ends: forgot password (staff reset only, no contact shown: B3); sudden block when a document expires (B16); app version breakage (B13); no cash ceiling (B5); no complaint form in the app (L11).
* **Driver (office-linked)** — wallet card "managed by your office", cash visible: works as J4 specifies (API `/wallet`, `/driver/overview`, notifications checked). Dead end: stranded balance at link time (B4); office not shown cash (B6).
* **Office** — invites, agreements, opportunities, assign/replace, settlements, wallet/withdraw, reports. Dead ends: no cash view (B6); drivers must register themselves and be invited by phone (no office-created driver accounts — staff can create them); payroll breakdown (B4 decision) only through the earnings report/workbook, not a per-period payroll sheet; no team (L1).
* **Staff presets** (`support`, `operations`, `finance`, `hr_verification` walked; `account_manager`, `reports` by catalogue only) — every sidebar page loads without 4xx. Findings: parcel search hidden (F1, fixed); dead permissions (B8); `demo.*` staff in the dev DB differ from their role (see Interplay 6); `/scenarios` visible to all staff.
* **Super admin** — settings, roles, staff, accounts, audit, finance, reports: complete, but no system status (B11), no company/legal settings (B3), no privacy tools (B10), no bulk actions (L5), broadcast by role only (L4).
* **Public recipient** — `/track` works (generic 404 for wrong code/digits, rate-limited, stage only). Gaps: no ETA/actions (L3); no SMS in production (B2); no contact for JR (B3).
* **API / partner integrators** — create/read/events/shipments + signed webhooks + five warehouse-system adapters. Gaps: B12; Omniful return endpoints answer VALIDATION_ERROR by decision I15.

### API without UI / UI without API
* Features in the API but not in the UI: `POST /admin/offers/:id/resolve-dispute` (dead), `GET /admin/reports/:type` (legacy), the public job API and the carrier/partner endpoints (by design). Web driver portal does not send GPS (`/driver/location` is app-only), so the admin live map only shows app drivers.
* In the UI but weaker than the API: `attendance.edit` button gating (B8).
* Nothing in the UI calls a route that does not exist.

## 7. Interplay problems of the latest changes (J, E16/E18, roles)

1. **J4 × wallet:** stranded balance, invisible to staff (B4).
2. **E17 × E18:** cash never touches the wallet while earnings are paid immediately → no netting/lien (B5, O6).
3. **E9 default × J1 (SMS only for recipients) × no adapter:** B2C delivery blocked in production (B2).
4. **E16/E18 remnants:** dead alerts, dead permissions/settings/route/state, stale landing copy and TRACEABILITY (B7, B8).
5. **J1 × support:** no self-service reset and no public support contact; lockout (5 wrong / 15 min) has no owner-visible unlock for non-staff except resetting the password (B3).
6. **J8 roles drift:** in the dev DB 5 of 11 staff accounts hold permissions different from their role (e.g. `demo.ops` 13 vs role 19, missing `cod.manage` → no Finance › COD item; `demo.hr` 8 vs 11). The Roles page flags it (`differs`) and a role save re-aligns, but there is no "apply role to members" button and system roles never pick up new factory permissions after a release (`ensureRoles` inserts only missing rows). Add a one-click "align members" and a release note when presets change.
7. **J3 B2B off × marketing:** the landing page sells "Business to business (B2B)" deliveries with receipt proof while the platform default refuses B2B parcels (`B2B_DISABLED`).
8. **J2 routing off × docs:** SRS MOB-003, FLOWS 12 and landing still describe optimised routes; owner decided off (default). Update docs; keep Google code.
9. **J7 Finance › Drivers × office drivers:** wallet columns `null` for them, no "Finance › Offices" to see where their money went (B4, L10).
10. **E11 single active job × offices:** not verified (no evidence either way) — left out.
11. **B7 credit line × invoices:** postpaid debt has no statement/overdue flow (L6).
12. **Landing page vs product:** "paid out only after confirmed completion and ops approval", "confirm attendance and quantities", "Scenario MCQs (48)" (page holds 78) — copy not updated for E3/E16/E18 (B8, B15).

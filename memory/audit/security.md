# Audit K — A1 Security and access control (2026-11-21)

Scope: every route in `web/src/server/api/routes/*.ts` (368), `server/auth/*`, `server/api/router.ts`, `next.config.ts`, storage/uploads, webhooks / partners / API keys, exports, and the newest code (username login, register, username-available, reset-password / username / credentials, roles API, finance drivers, readable CSV, workbook exports, public `/track`).

Method: read the code paths, then **prove**: (a) a route inventory built from the TypeScript AST — `web/scripts/route-inventory.ts` (`npx tsx scripts/route-inventory.ts [--json|--flags]`: auth spec, zod body/query, guards reachable through the call graph, flags; pinned by `tests/unit/route-inventory.test.ts`); (b) black-box suites that call every route handler with real ids — `web/tests/integration/audit-a1-access.test.ts` (7 sections, 17 tests); (c) reproductions on the dev server and micro-benchmarks. `routeTable()` was added to `router.ts` (read-only view) for the tests.

## Summary
**Findings: 2 high, 4 medium, 3 low fixed; 3 medium/low need an owner decision; 4 cross-area notes.** No critical.
Route inventory: 368 routes — 179 `backoffice`, 36 driver, 29 business, 23 office, 26 `user`, ~24 shared role lists, **31 public** (all authenticate with credentials in the body, a key / token / signed link, or serve non-private facts — the list is pinned by a test, so a new public route fails it). 86 non-backoffice and 105 backoffice routes take an `:id`.
Proven by tests: (1) a staff member with **no permission** gets FORBIDDEN (or the documented masked 404) on **every** `backoffice` route called with real ids; (2) a second business, driver, courier office, a staff member with unrelated permissions and one with none cannot read or change another party's request, job, parcel, proof/media, custody, ticket, attachment, complaint, document, invoice, API key, partner connection, invitation or agreement through any of the 86 non-backoffice `:id` routes (with valid bodies, so the answer comes from the access check, not from validation) — and the owners **are** let in (positive controls); (3) company / office portal reports ignore forged `company` / `office` / `driver` filters, JSON and CSV; (4) a staff member holding every permission except `drivers.sensitive` receives no full phone, IBAN, bank or national id from any backoffice GET (294 URLs × JSON and CSV, incl. every analytics table and explorer dataset; 541 answers).
No IDOR, no cross-tenant write, no SSRF, no SQL built from input, no secret in a response was found. `npm audit --omit=dev`: 0 vulnerabilities (dev-only: 11 moderate in the eslint toolchain).

## Needs owner decision
* **A. Phone ownership (#10).** Recommended default: keep registration as decided (J1), but (1) do **not** link pending office invitations at registration — link them when the person's phone is verified by staff (documents approved) or when the office confirms the driver; (2) show the office the driver's name as registered, so a mismatch is visible. Cheap and reversible: (1) is two lines in `registerUser`. Not implemented because it changes the J1 contract.
* **B. Impersonation by credential reset (#11).** Recommended default: keep `accounts.edit` for resets (there is no self-service reset), but add a **cooling-off** — a payout-IBAN change made in the first 24 h after a staff reset is held for finance's review and flagged on the withdrawal screen ("IBAN changed 3 h ago, password reset by …"). Alternative: reset of a **driver / office** needs `drivers.sensitive`.
* **C. Account lockout as a denial of service (#12).** Recommended default: lock per account **and** address (a lock set by address X does not stop the owner from another address), or exempt `admin` from lockout and rely on MFA + the per-ip failure bucket. Today's lock is simple and pinned by tests; not changed.
* **D. Public enumeration oracles that exist by design:** `GET /auth/username-available` (60 / min / ip), the 409 `details.field` on `/auth/register` (username / phone / e-mail taken) and the "locked" answer after 5 wrong passwords reveal that a username exists. Recommended default: keep (the forms need them); the registration limit (5 / h / ip, prod) and the per-ip failure bucket bound them. A CAPTCHA / proof-of-work in front of registration is the next step if it gets abused.
* **E. Role edits and `assertCanManage`.** A non-admin with `staff.manage` may edit a role whose members hold permissions the editor lacks (they can only *remove* permissions from them, never add one they do not hold) — the account screen forbids exactly that for individual accounts. Recommended default: refuse editing / resetting / deleting a role whose permissions are not a subset of the actor's (admin exempt). Not done: it changes `roles.test.ts` expectations and is a product rule.

## Cross-area
* **A5** `components/features/admin-order-map.tsx:50` `mk.bindTooltip(p.label)` — Leaflet renders a string as **HTML**. Today the labels are server-generated (`code · status`), so it is not exploitable; any future user-supplied label (recipient name) would be stored XSS in the admin session. Wrap with the `esc()` helper already used in `route-map.tsx` / `GeoMap.tsx`.
* **A5** `e2e/crawl.spec.ts:30` lists `/scenarios` in `PUBLIC` and `e2e/crawl-lib.ts:37,142` treat it as a shared page: signed-out visitors are now redirected to `/staff/login`, staff without `settings.view` to their home.
* **A7** `.env.example` ships `CRON_SECRET=change-me` and the code accepts any non-empty secret (and `AUTH_SECRET` is only checked when first used: MFA / integrations fail closed at use, not at start). Refuse a weak / default `CRON_SECRET` and a missing `AUTH_SECRET` at boot in production. `INTEGRATIONS_SECRET` likewise.
* **A8/A3** `activity-sources-b.ts:109` and `details-users.ts:34` match failed sign-ins without a user id by the person's **phone / e-mail**; since J1 the stored identifier is the username, so a user's "failed sign-ins of an unknown name" no longer appear on his security tab (known-user failures do).
* **A2** the 4 MB JSON cap applies to every route; `POST /jobs` (public, X-API-Key) parses the body (zod) *before* the key is checked — unauthenticated callers can make the server validate 4 MB bodies. Low; move the key check before the parse if it ever matters.

## Checked and fine
* **Auth core.** Session = 32 random bytes, only the hash stored; web cookie `HttpOnly; SameSite=Lax; Secure` in production, 7 days (mobile 30); password change keeps the current session and revokes the others; staff reset / suspend / permission change revoke all; `resolveSession` reads the user row on every request so role changes apply at once; suspended users cannot sign in or use a session; MFA (TOTP, 8 attempts / 15 min, recovery codes hashed, replay window is the documented open risk); forced password change and forced MFA enrolment are enforced server-side in `dispatch`; Server Component layouts guard each portal.
* **Username login** (`/auth/login`, `/auth/staff/login`, `/auth/register`, `/auth/username-available`, `/auth/change-password`): generic 401 for unknown / wrong, atomic lockout counter, NFKC + lower-case normalisation, reserved names, password policy applied on every path (register, change, staff create / reset, account create), no OTP endpoints left, `otp_codes` only purged, `GET /auth/demo-accounts` 404 outside demo mode and `DEMO_MODE` cannot be on in production without the long acknowledgement.
* **Staff management.** `assertCanManage` / `assertGrantable` on reset-password, reset-MFA, unlock, update, create; `target()` in `account-credentials.ts` hides admins (404) and applies `accounts.edit` vs `staff.manage`; the roles API refuses unknown permissions, empty roles, self lock-out, granting what the actor does not hold; role changes propagate to members in the same transaction and are audited.
* **Authorization.** Every `[business, staff, admin]` handler uses `u.id === r.businessId || can(u, "requests.edit")`; `jobAccess` / `requestAccess` mask existence (404); documents, ticket attachments, proofs, media: owner / assigned party / the right permission only; offices reach only their own drivers, jobs, invites, agreements; partner connections and orders are scoped by `scopeId`; API keys: hash only, shown once, max 5, scoped, 120 / min / key, idempotency claimed atomically.
* **Exports.** `finance.view` + `reports.export` before any query, audited, formula-safe `csvLine` (leading `= + - @` tab, CR guarded; plain negatives pass), `Content-Disposition` names come from enums / sanitised refs, xlsx text is inline strings (never formulas), money / phone columns stripped server-side.
* **Input and injection.** Zod on every body (the only open-ended record is `PATCH /profile`, whitelisted field by field in `updateProfile`); 4 MB JSON / 12 MB upload / 64 KB hook caps enforced while streaming; the few `sql.raw` calls are fed by constants / whitelists (`finance-drivers-sql.ts`, `activity-sql.ts`, `details-*`); `LIKE` input escaped (`contains`); path params decoded safely.
* **Uploads and storage.** type list + header sniff (JPEG / PNG / WEBP / PDF), 8 MB, server-generated keys, local-disk prefix check, S3 / local fail-closed in production, sanitised stored names, `nosniff`, `private, no-store`, CSP `default-src 'none'; sandbox` on `/api`.
* **SSRF.** `isPrivateIp` (IPv4-mapped / NAT64 / 6to4 / site-local), validation + a single resolution, **pinned** connection (no DNS rebinding), no redirects, body caps, https only in production, credentials in URLs refused; partner HTTP goes through the same `pinnedFetch`; webhook URL tokens redacted from logs.
* **Public surface.** `/track` (code + last 4 digits, 30 / 10 min / ip and 20 / 10 min / code, one generic 404, stage only); partner hooks (constant-time token hash compare, per-ip and per-connection limits); Omniful carrier endpoints (key hash lookup, signed 1-h access token with version, per-key / per-client limits); signed label links (HMAC, per-purpose subkey); `/cron/tick` and `/health` deep (constant-time `CRON_SECRET`, fail closed when unset).
* **Headers / deployment.** `X-Frame-Options: DENY`, `frame-ancestors 'none'`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, COOP, HSTS in production, `poweredByHeader` off; Docker image runs as non-root, compose requires `AUTH_SECRET`, `CRON_SECRET`, `SUPER_ADMIN_PASSWORD`; `.env*` files are not tracked. Still open (documented): no `script-src` CSP (needs nonces), TOTP replay is read-then-write, `TRUSTED_PROXY` default `1` is spoofable when the app is exposed directly.
* **XSS sinks.** The only `dangerouslySetInnerHTML` is the constant theme script; no user text reaches `innerHTML` except the Leaflet tooltip noted above.
* **Dependencies.** `npm audit --omit=dev`: 0.

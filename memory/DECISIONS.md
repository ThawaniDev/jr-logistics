# JR Logistics — Decision Register (new platform)

Status: **implemented defaults awaiting owner confirmation.** The PRD/SRS (Appendix A) list 17 owner decisions. Where the owner has not
decided, the platform ships a **safe, configurable default** (never an invented legal/tax/financial rule). Anything marked ⚙ is editable at
runtime in *Admin → Settings* (audited) — no redeploy needed. Update this file whenever a rule is approved.

## Behaviours deliberately **not** carried over from the old system
Public demo-login for any account · OTP returned in production · fake "delivered" webhooks · non-atomic payouts · stuck escrow on rejected settlements ·
negative-refund double charge · 200/1000-row silent caps · duplicated state lists · local-time-as-UTC lateness · settlement left half-created on error ·
raw translation keys in the UI · hardcoded RTL toaster · password-less admin portal.

## Production readiness checklist (owner/ops)
1. Set `AUTH_SECRET`, `CRON_SECRET`, strong `SUPER_ADMIN_PASSWORD` (forced change at first login). 2. Schedule `POST /api/v1/cron/tick` every minute with `Authorization: Bearer $CRON_SECRET` (webhooks, offer expiry, office windows, request expiry, document expiry).
3. Connect an SMS provider (`setSmsProvider`) and payment provider (`setPaymentProvider`) — until then production refuses OTP/top-up instead of faking. 4. Configure durable object storage (or opt in to `STORAGE_DRIVER=local` on a persistent volume).
5. Enter approved pricing rules, agreements, terms text and policy values in Admin. 6. Back up Postgres and rehearse a restore. 7. Obtain legal/tax sign-off for items 5, 8, 9.

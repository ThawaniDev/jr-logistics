## Post-audit decisions (rebuild audited against the old system; defaults taken, change in Admin or code if the owner disagrees)
| # | Topic | Default now implemented |
|---|---|---|
| A1 | Billable quantity | Never above what was **booked** (the escrow only covers that) or **loaded**. Driver report, business confirmation, ops dispute resolution and finance correction are all capped; extra work = a new request. |
| A2 | Partly staffed requests | One hour after the start time the open slots are closed: the request continues with the drivers already assigned and the escrow for the empty slots is refunded (`maintenance`, event `unfilled_slots_closed`). |
| A3 | Settlement approval | With *separation of duties* on (default) a settlement must be **reviewed** by one person and **approved** by another; skipping review is refused. Finance may *correct the quantity* before payout (returns to review). After payout, use a manual wallet adjustment. |
| A4 | Manual money corrections | `wallet.adjust`/`refunds.manage` can post an audited, idempotent adjustment that moves money between a user wallet and the **platform** account (so books balance). It cannot overdraw either side. No automatic compensation (unchanged from #10). |
| A5 | Payout batches | Held (complaint) settlements are *skipped*, not failed; an empty batch is refused (409). |
| A6 | VAT | Settlement VAT now equals invoice VAT: extracted from the VAT-inclusive customer total (was margin-based in settlements). Tax owner still to confirm (#5). |
| A7 | Staff security | Nobody can grant permissions they do not hold or edit their own access. Admin can set a temporary password (forces change, unlocks, ends sessions). A temporary password blocks every API call except change-password/me/logout (server-enforced). Demo/test seeds clear the flag for the super admin (it is on the demo card); production keeps it. |
| A8 | Sensitive data | National ID, IBAN, bank and full phone are masked for staff without `drivers.sensitive`; dashboard money figures need `finance.view`. Payout-IBAN changes are audited and notify the owner. Uploaded files must match their declared type (header check). |
| A9 | Driver privacy | Addresses, recipient, contents **and notes** are visible only while the job is active (not after completion). |
| A10 | Office links | A driver can belong to one office; inviting/accepting across offices is refused. Joining/leaving expires *offered* offers so the payee snapshot (settlement) can never be wrong. An office cannot assign onto another office's reserved request. Office replacement offers go to the office's own drivers first. |
| A11 | Strike policy | Clearing a suspension also restarts the cancellation count (otherwise the next cancel re-suspends instantly). |
| A12 | External API | `Idempotency-Key` is claimed atomically (concurrent duplicates → one job, the loser gets 409 *in progress*); a failed create leaves no draft and frees the key. Saving the same webhook URL keeps the secret; rotation is an explicit action. |
| A13 | Publishing | Pickup and delivery addresses are required to publish; a preferred office must be verified with an accepted agreement. |
| A14 | Public site | The landing calculator shows **only** prices from approved platform rules ("from X", or "create a request" when none). Public `/terms` (live text + version) and `/privacy` (**draft, pending legal review**). |
| A15 | Alerts & dashboards | "Today" uses Saudi time (UTC+3); the unfilled-request alert uses `unfilledAlertHours`; cancelling a request is refused while deliveries await confirmation/settlement. |
| A16 | City matching | A driver only receives requests whose **pickup city equals the driver's city** (kept; phase 1 is Riyadh pickup). The driver app does not yet explain a city mismatch. |

## C-series — B2C + per-shipment delivery (from the owner's scenario answers, `mobile/JR-answers.md` + `JR-customized-answers.csv`)
The platform serves **B2B and B2C**: a warehouse/store ships parcels to individual consumers *and* to businesses. The old model (one request = a driver count + a single address + a typed-in quantity) was B2B-bulk only. Contract: `memory/SHIPMENTS_API.md`.

| # | Topic | Decision | Source |
|---|---|---|---|
| C1 | Manifest | A delivery request carries **one shipment per parcel** (recipient name, phone, address, type, optional externalRef/notes/pin). Required to publish (`MANIFEST_REQUIRED`). Driver count is **derived** (`ceil(N / perDriver)`, balanced); escrow = exactly `N × unit price`. Cars with/without driver keep the day-rate flow. Requests with no parcel rows (legacy) keep the count flow. | user brief, #16, #20 |
| C2 | Step-by-step | The driver works **one stop at a time**, in manifest order; every stop action on a non-current stop is refused (`STOP_LOCKED`). Per stop: arrive → deliver \| fail \| defer (once). The delivered count is **derived from parcels with valid proof**, never typed. | user brief, #63 (custom: no next stop until the previous is confirmed by scan) |
| C3 | Routing | **Static route, no optimiser.** Order = the manifest order; the driver reviews and **approves** it before stops unlock. `POST /driver/route/optimize` removed. | #19 custom |
| C4 | Proof of delivery | **Consumers (B2C): the recipient's 4-digit one-time code is mandatory** (derived from shipment id + version, SMS'd when their stop becomes current; 5 wrong tries lock it; resend ≤ 3 and retires the old code). **Businesses (B2B): the code, or a photo of the signed/stamped/ID-numbered receipt + receiver name.** Parcel scan/typing must match the current stop (code, the warehouse's own ref, or the manifest number). Pin distance is recorded, never blocks (pins are unvalidated input). | B1/B10, #60 custom, #64 |
| C5 | One city per request | Every parcel must be in the request's delivery city; another city = a separate request (a stray parcel breaks 25 other customers' slots). A parcel found out of zone/address wrong at the door is failed and returned. | #17, #42 custom |
| C6 | Failed stops & returns | Reasons: unreachable (arrive + wait `stopWaitMin`, default 10), refused, wrong_address, out_of_zone, closed, no_otp, damaged, gate_access, other. Failed parcels must be **received back by the warehouse (scanned)** before the job can be confirmed (`RETURNS_PENDING`); otherwise dispute → ops decides, leftovers become `missing`. **Failed attempts are not billed** (delivered only; the rest refunds). Mid-route diversion requests are not honoured — the parcel is returned (#21 custom). A driver who cannot continue **ends the route**: delivered stops stay paid, parcels on board become returns, an urgent ticket opens, the office is told. Replacement of a driver who already worked stops is refused in favour of ending the route. Re-ship = one click → new draft from undelivered parcels. | B2, #14–#22, #31/#35/#76/#77 custom |
| C7 | Allocation | A winner of a slot receives `ceil(pool ÷ slots left)` contiguous parcels, **capped at the per-driver plan**; the offer's booked units (→ escrow share, earning, refund) always equal what it really carries. Parcels the warehouse does not hand over return to the pool; parcels nobody carried are withdrawn at completion and their escrow goes back. | B5/B6, #1, #44 |
| C8 | No cash, no card terminals | There is **no COD** and **no POS/network devices** in custody (`pos_device`, `network_device` removed from handover types). | #23 / #24 / #26 custom ("preferably stop cash and network") |
| C9 | Office selection cancelled | A business can no longer reserve a request for one office (`preferredOfficeId` ignored, `/business/offices` removed, no exclusive window). Offices still see opportunities and assign their own drivers. | #47 custom |
| C10 | All-or-nothing | New checkbox `allowPartial` (default on = run with whoever accepted; the old behaviour). Off = if not every slot is filled by the start time the request is **called off and fully refunded**. | #48 custom |
| C11 | Public tracking & integrators | Recipients can track a parcel at `/track` with the code + last 4 digits of their phone (stage only, no address/driver). Integrators get `GET /jobs/:id/shipments` and `shipment_delivered`/`shipment_failed` webhooks. | B2C requirement |
| C12 | Volume/weight | Weight and volume are **not shipment fields** — sizes are agreed with the warehouse up-front (#9 custom). Capacity is the per-driver parcel count. | #9 custom |

## Audit fixes (server reliability / security audit)
Everything below is additive or a bug fix; old response shapes keep working. Each row is pinned by a test in `web/tests/integration/audit-*.test.ts` / `tests/unit/audit.test.ts`.
| Area | Found | Fix |
|---|---|---|
| Staff accounts (HIGH) | A staff member with only `staff.manage` could reset the password / second factor, unlock, suspend or re-permission a colleague holding permissions they lack, i.e. take over a more powerful account. | Non-admins may manage only staff whose permissions are a subset of their own (`assertCanManage`). |
| SSRF (HIGH) | `isPrivateIp` missed IPv4-mapped IPv6 in hex form (`[::ffff:7f00:1]`), NAT64, 6to4, site-local and some reserved IPv4 blocks. | IPv6 is parsed to groups; embedded IPv4 is judged; more reserved ranges. Applies to webhooks and partner base/callback URLs. |
| Money (HIGH) | `topUp` called the payment provider **before** checking the idempotency key: every retry charged the card again. | Key serialised with an advisory lock, ledger checked first; same key + other amount = `409`; provider outage = `503`. |
| Money | Concurrent payout batches both counted the same settlement (batch totals doubled). | Only the batch that really moved the money counts it. |
| Money | All-or-nothing call-off left a driver who was already confirmed/loaded live while the escrow was refunded. | Call-off cancels every live offer; loaded parcels become `failed(request_cancelled)` to be returned, like a cancelled request. |
| State | A business could record a driver no-show before the job started. | `409 INVALID_TRANSITION` until `startsAt`. |
| Retries | Re-sending a delivered / failed stop answered 409. | An exact repeat (same parcel code, same fail reason) returns the stop; nothing is applied twice. A different action is still 409. |
| Secrets | `GET /auth/me`, `/profile` and staff `/admin/users/:id` returned the business's webhook signing secret. | Removed; profile has `hasWebhookSecret` instead. The secret is shown once on set/rotate. |
| Requests | Unbounded bodies; malformed `%` paths and `Origin: null` caused 500s; client trace ids were echoed/logged raw; errors carried no `x-correlation-id`. | 4 MB JSON / 12 MB upload / 64 KB hook caps (`413 PAYLOAD_TOO_LARGE`, enforced while streaming); 4xx instead of 500; trace ids sanitised; the header is on every response. |
| Logging | `console.error(error)` printed Drizzle errors with bound parameters (IBANs, hashes). | One JSON line per failure (`src/lib/log.ts`): correlation id, route, scrubbed message, pg code, 6 stack frames. |
| Auth | Lockout counter was a read-modify-write (parallel guesses dodged it); OTP could be consumed twice by parallel requests; SMS provider outage = 500 with the provider's error text. | Atomic SQL; atomic burn; `503 DEPENDENCY_UNAVAILABLE`. |
| Abuse | No limits on job chat, document uploads, office invites, per-parcel tracking guesses; `rate_limits`/sessions/OTP/idempotency rows never deleted. | Limits added; maintenance purges stale rows (`housekeeping`). A crashed idempotent API call no longer blocks its key forever (reclaimed after 2 min). |
| Input | Money amounts could overflow Postgres integers (500); unbounded strings/arrays/coordinates. | Zod bounds; Postgres range errors now map to 422. LIKE wildcards in search text are literal. |
| Data | A ticket tied to your offer could also be pointed at someone else's request; drivers/offices saw the customer price (`totalCents`) in job timelines; local storage prefix check accepted a sibling folder. | Fixed. |
| Partners | A partner timestamp in the future froze the parcel status; attacker-chosen ids created rate-limit rows. | Future times are clamped to now; id validated first. |
| Integrity | Enum-like text columns had no checks; hot queries had no indexes; ledger/event ids had no FKs. | Migration `0007_audit_hardening` (indexes, `NOT VALID` checks, FKs, partial unique indexes). |
| Operability | `/health` only did `select 1`. | Public: status + db latency. With `Authorization: Bearer $CRON_SECRET`: scheduler freshness (`degraded` if no tick for 10 min), webhook/outbox backlog and dead-letters, provider config. |
| B7 credit line | Decision B7 was listed as implemented but did not exist. | Implemented as the default: `wallet_accounts.credit_limit_cents` (migration `0008`), `available` may go to `-limit`; publishing beyond it = `402 CREDIT_LIMIT_EXCEEDED` (otherwise `INSUFFICIENT_FUNDS`); staff set it with `POST /admin/finance/credit-limit` (`wallet.adjust`), audited, never below the debt already carried. Stored on the wallet (not `business_profiles`) because the database CHECK lives there. |

| D5 | When the route is planned | Automatically when the warehouse **hands over** (best effort, never blocks it); the **driver can re-optimise** (`POST /offers/:id/route/optimize`, optional GPS origin) before **and after** approving — after approval the stop the driver is standing at stays first and only the not-yet-reached stops move. | D6 | Cost | Google bills Routes **Pro** (traffic-aware + waypoint optimisation) per call: a 30-parcel driver = 2 calls. Key: `GOOGLE_MAPS_API_KEY` (server only); enable **Routes API** and **Geocoding API** on it. |

## Production readiness checklist (owner/ops)
1. Set `AUTH_SECRET`, `CRON_SECRET`, strong `SUPER_ADMIN_PASSWORD` (forced change at first login). 2. Schedule `POST /api/v1/cron/tick` every minute with `Authorization: Bearer $CRON_SECRET` (webhooks, offer expiry, office windows, request expiry, document expiry).

8. Set `TRUSTED_PROXY` to the number of reverse proxies in front of the app (default `1`; `cloudflare`; `none` if exposed directly). Never enable demo mode on a public production site: the demo card exposes the super-admin credentials by design on demo/test deployments (owner-approved for testing).
10. Housekeeping: either set `INTERNAL_SCHEDULER=true` (runs inside every app instance, one at a time via a Postgres advisory lock) or call `/api/v1/cron/tick` every minute (required on serverless hosts). 11. Documents: set `STORAGE_DRIVER=s3` + `S3_*` (AWS S3 / Cloudflare R2 / MinIO), or keep `local` on a persistent volume (single node only).
